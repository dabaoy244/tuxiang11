[7] 2026-09-25 17:20 新增 —— 修「stage2 第 1 个 epoch 就崩：AttributeError: 'float' object has no attribute 'backward'」
    ★ 这是 [6] 修好之后**才第一次有机会被执行到**的 bug：stage1 连跑 20 轮都不触发。
    · 根因（数据成分比例 × 损失函数）
        stage2 只启用 loc/edge，这两个任务的监督项（bce/dice/edge）**全部来自像素掩码**；
        训练集是 ForenSynths（无掩码 4 万张）+ CASIAv2/COVERAGE（带掩码 6120 张）的混合集，
        掩码样本约 13% ⇒ batch=16 时 (1-0.133)^16 ≈ 10% 的批次**一张带掩码的都没有**。
        此时 MultiTaskLoss 的 raw 为空，而 UncertaintyWeighting 里的 `total = 0.0`
        始终没被替换成张量 → total 是 Python 浮点 → `loss.backward()` 直接抛异常。
    · src/losses/multi_task.py
        a) 新增 `zero_loss(outputs)`：raw 为空时返回**挂在计算图上的 0 张量**
           （`v.sum()*0.0`，可安全 backward、梯度全零），而不是浮点 0.0。
        b) 返回体新增 `empty` 标志（= raw 为空），供训练循环据此跳过参数更新。
        c) `UncertaintyWeighting.forward` 改为 `total=None` 起手，一项都没匹配上就
           **显式抛错**（带调用栈），不再把"空输入"静默降级成浮点 0。
    · src/engine/trainer.py
        a) `_train_one_epoch` 在 **backward 之前**跳过空批次（continue）：
           既不 backward 也不 opt.step，且**不计入平均损失**
           （否则 loss 曲线被 0 稀释成"看起来在变好"）。
        b) epoch 结束若出现空批次则打印数量；**整轮有效批次为 0 则硬失败**，
           报错直接指向"CASIAv2 / COVERAGE 是否 0 条"（正常占比 ~10%，100% 只可能是
           带掩码的数据集没加载进来）。
        c) `fit(start_stage=N)`：**跳过已完成的阶段**。配合新增的
           `scripts/train.py --start-stage <名字|序号>`，可以从 stage2 直接续训，
           不必重跑已训完的 stage1（约 100 分钟卡时 / ¥3）。
           跳阶段时会把 global_epoch 顶到前面阶段的总轮数上，保证 β 退火接得上。
    · scripts/cloud_autodl.sh
        `train` 后面可以跟任意 train.py 参数，原样透传。例：
            bash scripts/cloud_autodl.sh train --resume checkpoints/vibnet_best.pt \
                --start-stage stage2_loc_pretrain
    · scripts/smoke_test.py
        新增【8】空批次守卫（三种任务组合 / 有·无掩码 / 跳过计数 / 整轮全空硬失败）
        与【9】跳阶段续训（只跑 stage2+stage3、global_epoch 承接、越界收敛、

[10] 2026-09-27 新增 —— 修「stage2 比 stage1 慢 8~14 倍」的真根因：
     **bf16 的双线性上采样反向掉进慢路径（单次 2.9 s，fp32 只要 ~7 ms）**
    ★ 这一条把"全量三段重跑"从"根本跑不完"变成"约 9 小时"，是能交付的前提。
    · 根因（一句话）
        `F.interpolate(mode="bilinear")` **不在 autocast 的 fp32 提升名单里**。
        autocast 下 `d1` 是 bf16（conv 的输出就是 bf16）⇒ 定位支路那次
        14²→224² 上采样按 **bf16** 执行 ⇒ CUDA 的
        `aten::upsample_bilinear2d_backward` 对 bf16 走**未向量化的 atomicAdd 慢路径**：
        单次 **2.9 s**（fp32 ~7 ms，差 400 倍）。
        stage2 启用 loc/edge ⇒ 这条反向不被剪掉；stage1 只用 cls ⇒
        定位支路的反向被 autograd **整段剪掉**（前向照跑）⇒ stage1 完全看不到。
    · 证据链（`torch.profiler` 只包 backward，直接点名）
        aten::upsample_bilinear2d_backward   4 次   CUDA 2.909 s   占 97.19%
        其余全部算子合计仅 ~90 ms（conv_bwd 27.8 / BN 12.8 / mm 12.2 / flash-attn 2.4）
        合成对照把触发条件钉死：fp32 输入 29.4 ms / **bf16 输入 2988.7 ms** /
        `conv→interp`（interp 输入为 bf16）2977.3 ms / 同链 nearest 4.8 ms
        ⚠ 早前 `scripts/bench_upsample.py` 测出 16.5 ms 就"排除上采样"是**假阴性** ——
          它建的是 **fp32** 张量。**排除性微基准必须用真实 dtype 复现。**
    · src/models/mobile_unetv2.py（★ 核心修复）
        新增 `_bilinear_upsample_fp32(x, size)`：
            with torch.autocast(device_type=x.device.type, enabled=False):
                return F.interpolate(x.float(), size=size, mode="bilinear", align_corners=False)
        两处调用全部改走它：MobileUNetV2 输出层那次 14²→224²（主凶）与
        UpBlock 内的 2 倍上采样（再 `.to(skip.dtype)` 保证 cat 成立）。
        下游 conv 在 autocast 下会自动转回 bf16 ⇒ **数值只更精确**，语义等价。
    · 实测收益（`scripts/diag_seg.py` 同一把尺子）
        stage2 bwd  3065.3 → **159.3 ms**（default）、2994.9 → **115.8 ms**（fused）
        stage2 单步 3.13 s → **0.23 s（约 14 倍）**，且与 stage1 回到同一量级
    · src/engine/trainer.py
        a) 优化器优先用 **fused AdamW**：默认实现走 `_single_tensor_adam`，
           每步对每个标量参数做一次 `.item()`（本模型实测 402 次/步），
           fused 是 **0 次**。非 CUDA / 不可用时自动回退，并把所用路径写进日志。
        b) `_monitor_value` 的 KeyError 增加一条最可能原因的提示
           （"本轮验证集没有带掩码样本" / `--limit-batches` 截断验证集）。
    · scripts/train.py
        `--limit-batches` **只截训练集，不再截验证集**：验证集顺序是
        ForenSynths(8000 张、无掩码) 在前、CASIAv2(1261 张、带掩码) 在后且
        shuffle=False ⇒ 截断后前几百批**必然**没有掩码样本 ⇒ validate() 不产出
        loc_* ⇒ stage2 的 monitor=val_loc_miou 抛 KeyError。
        （验证集只有前向，跑满一轮约 40 s，冒烟完全付得起。）
    · scripts/smoke_test.py
        新增【11】上采样强制 fp32（行为断言：bf16 输入/autocast 下均返回 fp32；
        AST 断言：两处调用均经由 helper、无裸 F.interpolate；优化器含 fused 分支）
        与【12】`--limit-batches` 不截验证集（源码断言，含反向断言"训练集仍被限流"）。
        自检 58/58 → **60/60**。
        ⚠ 教训：源码断言**必须用 AST**，不能用正则 —— 该模块文档字符串里就写着
