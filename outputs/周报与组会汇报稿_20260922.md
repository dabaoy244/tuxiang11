**3. 数据集全部到位（此前最大的阻塞项已解除）**

| 数据集 | 规模 | 状态 |

| ForenSynths `train` | **74.9 GB / 20 类 720119 张**，7 卷 | ✅ 已下载并通过结构级校验 |
| CASIA v2.0（定位） | **7491 真实 + 5123 篡改 + 5123 掩码 = 17737 文件** | ✅ 完整 |

**4. 定位并验证了"模型训不动"的根因（本周最关键的技术结论）**
- 现象：真实数据上训练时，模型退化成"把所有图都判成伪造"，判决边界不存在。
- 根因：**骨干随机初始化**——没有预训练权重的 ViT 在几千张图上建立不起判决边界。
- 验证方式：做了**受控对照实验**，两臂除 `backbone_weights` 外完全一致
  （配置过滤注释后只剩实验标签与落盘路径两处无关差异）。
- 判据**不看准确率，看混淆矩阵里 `tn` 和 `tp` 是否同时为正**：
  - 随机初始化臂：`tn = 0` / `tp = 650` → **退化，全判一类**
  - 预训练权重臂：`tn = 163` / `tp = 582` → **有效，判决边界已建立**
- **如实说明**：两臂排序指标 AUC 只差 +0.038，所以结论是
  「预训练权重是边界能建立的**必要条件**，**远非充分条件**」——
  要达到申报指标，还需要完整三阶段训练 + 全量训练集 + GPU。

**5. 修正了申报书/配置里一处错误断言（自我纠错）**
- 原 `configs/ablation_b16_*.yaml` 与 `docs/14` 声明「验证集与训练集图像无交集」，
  这个断言从未被验证过；本周用**内容哈希（MD5）审计**后发现**它是错的**：
  池级有 **400 张真图逐字节重复**，且非常集中（`cat` 200/200、`horse` 200/200 整类命中）；
- 同时发现"只比文件名"会犯两种相反的错：漏掉同图异名（只见 422 个同名）、
  误报同名异图（`car` 那 22 个是同名但两张不同的图）；
- 已改正声明，并实现了**内容级去泄漏机制**（生成排除清单 → 评测前剔除候选）。

**6. 外部数据集审计与接入（同伴提供的 2832 张）**
- 审计发现：该数据存在**平凡可分捷径**——只看"是否 PNG"这一个比特，
  AUC 就达到 **1.0000**（伪造侧全 PNG/512×512，真实侧全 JPEG/分辨率各异）。
  直接使用会拿到**虚高**指标，且频域支路会优先学到"压缩格式"而非"生成痕迹"；
- 已改造为干净测试域：**1416 对**（14 个交集类别逐类 1:1、统一 512×512 JPEG q=90），
  并保留"处理前"基线做对照；
- 数据出处为 GenImage `train` split → 本项目只做**零样本测试**，
  现有权重从未见过它，用法干净。

**7. 工程质量**
- 全项目自检 **34/34 通过**（含指标口径、数据审计、分卷直读、去泄漏等回归断言）。

## 四、需要主动向老师说明的一处"指标口径调整"

**申报书里有一处内部冲突，必须让老师知情**：

申报书同时要求三个条件：① 用 **CLIP-ViT-B/16** 骨干、② 体积 **≤120 MB**、③ CPU **≥8 张/秒**。
但这三条在 FP32 下**无法同时成立**（b16 实测：**362.1 MB / 2.86 张/秒**）。

**建议方案（推荐方案一）**：

| 方案 | 内容 | 风险 |
|---|---|---|
| **方案一（推荐）** | 主模型改用**轻量档 s16** → 体积 98.7 MB ✅ + 9.46 张/秒 ✅ **两项同时达标**；<br>CLIP-ViT-B/16 作为**高精度对照档**在同一篇论文里报精度上限 | 低。**一条标准都没降**，只是把"用哪个骨干"这个前置条件写清楚，反而多一组对照实验 |
| 方案二 | 坚持 b16，但把"CPU ≥8 张/秒"改成"≥8 张/秒（轻量档）/ GPU 部署主档" | 高。这是**降低标准**，评审敏感 |

## 六、可能被追问的问题（提前背下来）

**Q：之前的训练为什么训不起来？现在凭什么能？**
> 根因是**骨干随机初始化**——没有预训练权重的 ViT 在几千张图上建立不起判决边界。
> 我们做了受控对照实验：两臂除骨干权重外完全一致。**判据不是准确率，而是混淆矩阵里
> `tn` 和 `tp` 是否同时为正**：随机初始化臂 `tn=0`（把所有样本判成伪造，边界根本不存在），
> 预训练臂 `tn=163 / tp=582`（两类都能判对，边界建立起来了）。
> 同时如实说明：两臂 AUC 只差 +0.038，所以我们的结论是"预训练权重是**必要条件**、
> 远非充分条件"——要到申报指标还得靠完整三阶段训练 + 全量训练集 + GPU。

**Q：数据量够吗？**
> 分三层：① ForenSynths `test` 已完整清点，**90329 张 / 13 种生成器**（官方 90310，吻合）；
> ② `val` 20 类 8000 张；③ `train` 已下完 **74.9 GB / 20 类 72 万张**。
> 如果最终只用 4 类子集，会明确写明训练集范围。

**Q：mIoU 怎么算的？**（定位指标最容易被追问）
> mIoU 至少有三种定义，同一模型能差一倍以上，所以我们**三种都算、都报，并写明判定用哪个**：
> ① 池化（最宽松，只看训练趋势）；② **仅篡改图逐图平均——这是 ManTra-Net / SPAN / CAT-Net
> 的可比口径，我们论文报这个，也是达标判定口径**；③ 全部非空图（最严格）。
> 三种口径的定义用回归测试钉死，改实现就会报警。

**Q：一个人做得完吗？**
> 核心必做项已锁定（四条硬指标 + 软著 + 论文各 1 项），非核心项按优先级砍。
> 砍的顺序：第 2 篇论文 → 20 类全量 → 消融项 → 对比实验数量。

**Q：为什么用 VIB？**
> 抑制纹理细节带来的过拟合；而且**频域 + VIB 两个创新模块合计只占 0.8% 参数**，几乎零成本。

**Q：大模型时代，CLIP 权重哪来的？**
> 如实说：受限网络下 CLIP 权重未取得，对照实验用了 **ImageNet-1K 预训练 ViT-B/16**
> （同为 ViT-B/16 结构）作为替代。代码支持三条加载路径（本地 CLIP 目录 → HF 名称 →
> 兜底骨干 + 本地权重），拿到 CLIP 后无需改代码即可切换。
