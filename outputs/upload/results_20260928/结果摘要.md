## 五、四条必须处理的口径问题

1. **`targets.CPU 推理 >= 8 张/秒` 判 `true` 是错的。** 同一份 JSON 写着 `"device": "cuda"`，
   2220 张/秒是 4090 的数。真实 CPU 吞吐见 `docs/09`：b16 无论 FP32/INT8 都只有 2.86 张/秒，
   换 `configs/lite.yaml`（s16 骨干）才到 9.46~11.22 张/秒。需在 CPU 上按 `--bench` 重测。
2. **评测 A 与评测 B 的 `loc` 段逐位相同** —— A 的定位子集就是同一批 1263 张 CASIAv2 test，
   定位只被测了一次，不构成独立证据。
3. **ForenSynths 单数据集 ACC 未测**，91% 这条现在无数据，不能声称达标。
4. **COVERAGE 目录缺失**（`COVERAGE/train` 不存在），跨数据集定位泛化无数据。
