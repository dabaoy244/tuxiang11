# COVERAGE 外部域「随机水平」的取证备忘

日期：2026-10-01　权重：`outputs/ablation/full/ckpt/ablation_full_best.pt`（云端）
触发问题：「AUC 全部落在 0.546~0.591 = 随机水平，零样本跨伪造类型没有可用鉴别信号」——这说明了什么？

## 一、结论（先说硬的部分）

1. **分类侧的结论稳健，不是阈值造成的。**
   `full` 的 AUC = 0.5626。AUC 与阈值无关，所以它本身就是"排序能力"的度量。
   按 Hanley–McNeil 近似，n₁=91 / n₀=100 时 AUC 的标准误 ≈ 0.041
   ⇒ z ≈ 1.5，p ≈ 0.13。8 行里最高的 −相位支路 AUC 0.5910 也只有 z ≈ 2.2（且 8 次比较下不可信）。
   **⇒ 分类确实没有可靠的跨伪造类型鉴别信号。**
   另证：AUC 已被钉在 0.56，均衡类下最优阈值的 ACC 上界也就在 0.55 附近
   ⇒ 换阈值救不回来（这解释了为什么各臂 ACC 在 0.50~0.57 之间乱跳）。

2. **定位侧的报告值「mIoU★ 0.1106」低于平凡几何基线 —— 这是本轮新增的硬发现。**
   在**同一批 91 张篡改图**上（`scripts/coverage_trivial_baseline.py`）：

   | 平凡基线（不需要任何模型能力） | mean IoU |
   |---|---|
   | 全零预测 | 0.0000 |
   | 随机位置同面积框（解析期望） | 0.0631 |
   | **整图全判为篡改** | **0.1168** |
   | **居中正方框（面积对齐 GT）** | **0.1340** |
   | ← 模型 full 实测 `miou_tampered_only` | **0.1106** |

   ⇒ 模型**低于**"整图全判篡改"和"居中框"。
   之所以看起来"非零"，是因为 COVERAGE 的 copy-move 区域本身很大（GT 面积占比均值 **0.1168**），
   任何成块的预测都能蹭到部分重叠。

3. **机制：定位头在域外「几乎不激活」，不是"乱猜」。**（`scripts/coverage_loc_head_probe.py`）

   | 量 | 值 |
   |---|---|
   | mask_prob 均值 | 0.1486 |
   | mask_prob p90 | **0.2947**（九成像素概率 < 0.29 ⇒ 概率场整体没抬起来） |
   | 预测面积占比（thr=0.5） | 均值 0.1617 / **中位 0.0232** |
   | GT 面积占比 | 0.1168（⇒ 中位预测面积欠了 ~5×） |
   | 预测质心偏移（归一化） | 均值 0.1639（**不在中心**，排除"只猜中间"） |

4. **报告的 0.1106 是"阈值主导"的产物，但换阈值也过不了平凡线。**
   （`scripts/coverage_loc_threshold_sweep.py`，91 张篡改图）

   | thr | meanIoU | medIoU | 预测面积 |
   |---|---|---|---|
   | 0.05 | 0.1320 | 0.1161 | 0.3085 |
   | 0.10 | 0.1263 | 0.0935 | 0.2769 |
   | 0.30 | 0.1173 | 0.0452 | 0.2182 |
   | **0.50（报告口径）** | **0.1106** | **0.0044** | 0.1617 |
   | 0.70 | 0.0821 | 0.0000 | 0.0598 |

   - meanIoU 随阈值**单调**变化 ⇒ 这个指标主要在被"预测块有多大"驱动，而不是被"放得准不准"驱动。
   - 默认操作点下**中位 IoU 只有 0.0044** ⇒ 一半以上的篡改图**完全没有重叠**；
     mean 0.1106 是被少数"大块"图拉起来的。
   - **即使取在测试集上挑出来的 oracle 阈值（0.05），0.1320 仍不过居中框基线 0.1340。**

5. **8 行的臂间差异全在噪声内，不要当排名读。**
   n=191 时 ACC 的标准误 ≈ √(0.25/191) ≈ 0.036（95% CI 半宽 ≈ ±0.071）；
   8 行 ACC 的极差只有 0.5026→0.5654 = 0.063，**小于一个置信区间**。
   ⇒ "−CS-CAM 在 COVERAGE 上 ACC 最高"之类的读法不成立。

## 三、该怎么用（写材料时的口径）

- **不要把这一列与 ManTra-Net / SPAN / CAT-Net 的 COVERAGE mIoU 并列做能力比较。**
  该列口径是刻意对齐它们的，读者一定会横向比；而 0.11 落在平凡几何基线带内。
  且那些方法是在**同域/含 COVERAGE** 的条件下评测的，本表是**零样本**，本身不可比。
- 正确的定位：这是**边界条件（limitation）**，不是主结果。
  可主张的是 ForenSynths 跨生成器 + CASIAv2 的域内结果；跨**篡改类型**的零样本迁移**失败**。
- 机制解释可以写实：「模型学到的是**合成图指纹**类判别特征（训练集以 ForenSynths 生成图为主），
  而 COVERAGE 是**真照片上的复制-移动**，线索是局部拼接边界 ⇒ 特征层面对不上。」
  证据：定位头概率场 p90 仅 0.29（不激活），且 8 个臂无论去掉哪个模块都无差别
  ⇒ 不是"某个模块缺失"，是**训练域线索本身不覆盖该任务**。
- 若要真做"跨篡改类型鲁棒性"，需要的是**协议级**改动（训练混合里加入真照片域的拼接/复制移动并平衡采样），
  而不是继续调模块。另建议补一个**阈值无关**的定位指标（逐图最优 IoU 或像素级 PR-AUC），
  否则"操作点没校准"与"没有信号"永远分不开。

## 四、附带修正（口径红旗，务必同步）

- 原备忘里「`no_phase` 的 COVERAGE mIoU★ 0.1329 > full 0.1106」曾被当作可疑信号；
  现在看得很清楚：**0.1329 ≈ 居中框基线 0.1340**，即它只是"预测块更大/更靠中"的几何巧合，
  不是定位能力。**该行一律不要做能力解读。**
