
| 问题 | 答复 | 影响 |

## 4. 三个必须知道的问题

### 4.1 ★★ 存在与「篡改痕迹」无关的平凡可分线索（最严重）

抽样 600 + 600 张，计算**与图像内容无关**的元信息特征，单特征对真/假的 AUC：

| 平凡线索 | AUC | 判定 |
|---|---|---|
| **是否 PNG 格式** | **1.0000** | ★★ 完美分开，**必须消除** |
| **每像素字节数**（压缩率） | **0.9954** | ★★ 几乎完美分开，**必须消除** |
| **原图分辨率** | **0.9050** | ★ 明显可分，应消除或说明 |
| JPEG 块伪影比 | 0.5238 | 无信息（重采样后 8×8 网格已对齐不上） |

具体数值：

```
真实：中位分辨率 187500 px，中位压缩率 0.5821 字节/像素，100% JPEG
伪造：    固定 262144 px，中位压缩率 1.6897 字节/像素，100% PNG
```

**后果**：只用「这张图是不是 PNG」这一个比特，就能把 1200 张样本**全部分对**。
也就是说，一个完全不学伪造线索的分类器，也能在这份数据上拿到接近 100% 的准确率。

**对本项目的特别警示**：本项目有**频域支路（2D-DFT 幅值/相位）**。
JPEG 有损压缩在频域留下的量化格栅、与 SD 输出（PNG 无损、但带扩散模型的频谱上采样伪影）
**在频谱上是两种截然不同的形态**。频域支路极可能学到「JPEG 格栅 vs 扩散频谱」
这个二分，而不是真正的篡改痕迹 —— 这会让指标虚高，且**跨数据集一定崩**。

**必须做的事**（顺序不能反）：
```text
1. 两侧统一重编码：同一格式（建议全部 JPEG q=90）、同一边长（建议长边 512）、
   同一次采样滤波器（建议 bicubic）。
2. 重编码后**重跑一遍 audit_flat_realfake.py**，确认三个平凡线索的 AUC 都落到 0.6 以下。
3. 若仍有 AUC > 0.8 的线索，说明清洗不够，不要进入训练。
```

### 4.2 ⚠ 两侧类别集合只重合 14 个

**为什么这是个问题**：由于 72 个类别**只出现在伪造侧**，71 个类别**只出现在真实侧**，
「这个类别」与「真假标签」是**一一绑定**的。
一个容量足够的模型完全可以学成「认得这是虎鲨 → 判伪造（因为训练里虎鲨只有伪造）」，
从而在测试集上表现很好，却**没有任何伪造检测能力**。

**处理方式（二选一，必须写进论文口径）**：
- **A（严格）**：只用交集的 14 个类别做内容可控对照（最多 1416 对 / 2832 张）。
- **B（宽松）**：全量使用，但在论文里**显式声明**类别不匹配这一限制，
  并**额外报一个只用交集类别的子集指标**作为对照。

> 注：两侧都取自 ImageNet-1k 的 1000 类，实际交集 14 > 随机抽样的期望 ≈ 7.3，
> 说明抽样确实与「类别」有关联，但**远没到成对的程度**。

### 4.3 ❌ 是整图生成，不是局部篡改 —— 不能用于定位支路

- 命名与内容都表明：`smallai` 是 **512×512 整图生成**（文生图/类别条件生成），
  不存在「原图 + 局部修改」的对应关系。
- 因此**没有像素级掩码**，`TamperDataset`（`kind: "tamper"`）无法使用它。
- 本项目的定位支路（mIoU 目标 ≥56%）必须继续依赖 **CASIA v2 / COVERAGE** 这类有掩码的数据。

> 术语对齐：本项目文档里
> **「伪造」（`kind: gensynth`）**= 整图生成（GAN/扩散/自回归，无掩码）；
> **「篡改」（`kind: tamper`）**= 传统局部篡改（有掩码）。
> 同伴说的「篡改的数据」按本项目口径应称**伪造 / 整图生成**。

## 5. 与本项目的关系：能做什么、不能做什么

### ✅ 值得做的：作为「第三个测试域」检验跨数据集泛化

这正是本项目**已实测的短板**：

| 评测域 | 已测结果 |
|---|---|
| ForenSynths 跨生成器（13 个生成器，同域） | 宏平均 AUC **0.6076** |
| CASIA v2（传统篡改，跨任务） | AUC **0.4920**（接近随机） |
| **smallai/smallnature（ImageNet + SDv1.4，跨数据源）** | **← 本批可补上这一格** |

意义：
- 现有训练集是 `ForenSynths`（按生成器分目录）+ `CASIAv2`。
  本批是**另一条数据来源链**（ImageNet 原图 + SDv1.4 类别条件生成），
  在**内容分布**上与 ForenSynths 明显不同（ForenSynths 多为人脸/物体小图）。
- 但要注意：**伪造类型上没有新增**（同样是扩散模型生成），
  所以它检验的是**跨数据源/跨内容分布**的泛化，不是跨伪造类型。
  若目标是覆盖传统篡改，仍必须靠 CASIA/COVERAGE。

### ❌ 明确不能做的
- 不能用于定位支路（无掩码，见 §4.3）。
- 不能直接当作「跨生成器泛化」的新生成器（只有 `sdv4` 一个生成器）。
- 不能在未做格式统一前训练或评测（见 §4.1）。

## 6. 接入现有流程所需的数据改造

现有 `src/data/datasets.py` 期望的目录约定是 `ForenSynths` 式的：

```
<root>/<生成器>/**/0_real/*.jpg     真实
<root>/<生成器>/**/1_fake/*.jpg     伪造
```

而本批是**扁平**的 `类别_标签_序号.png` / `synset_序号.JPEG`，两者不兼容。
有两种改法：

**方案 A（推荐，改动最小）**：把本批改造成 ForenSynths 式布局后再用现成的 `GenSynthsDataset`
```
data/Datasets/GenImageSDv14/test/
    sdv14/
        0_real/   <- smallnature（经统一重编码）
        1_fake/   <- smallai（经统一重编码）
```
这样 `configs/*.yaml` 里加一条 `- {name: "GenImageSDv14", kind: "gensynth", split: "test"}`
即可直接评测，**零代码改动**。
代价：类别信息在目录层面丢失（但文件名仍保留，需要时可按需恢复）。

**方案 B**：新写一个 `FlatRealFakeDataset`，在文件名里解析类别，
从而支持「按类别分层」「只用交集类别」这类更细的评测。改动更大，但更灵活。

先做 §4.1 的重编码是**两种方案共同的前置条件**。
