## 四、必须主动说明的一处"指标口径调整"（核心）

申报书写了「模型体积 ≤120 MB」与「CPU ≥8 张/秒」两条硬指标，
同时又要用 CLIP-ViT-B/16 骨干。**这两条在 b16 下无法同时满足**：

| 骨干 | FP32 体积 | INT8 体积 | CPU 吞吐 | 能否同时达标 |
|---|---|---|---|---|
| CLIP-ViT-B/16 | 362.1 MB ❌ | 88.6~92.9 MB ✅ | 2.86 张/秒 ❌ | **不能** |
| 轻量 s16 | **98.0 MB** ✅ | 25.7 MB ✅ | **9.46 张/秒** ✅ | **能** |

**处理方式（二选一，建议选方案一）：**

- **方案一（推荐）**：主模型改用轻量 s16 骨干，两条硬指标同时达标；
  CLIP-ViT-B/16 作为**高精度对照档**在同一篇论文里报告精度上限。
  → 这样既守住指标，又多了一组对照实验，反而更饱满。
- **方案二**：坚持 b16，但必须把「CPU ≥8 张/秒」调整为
  「CPU ≥8 张/秒（轻量档）/ GPU 部署主档」。⚠️ 注意：这是**降低标准**，
  评审敏感，必须给出充分理由（如主档面向 GPU 服务端部署）。

> 铁律仍是 `docs/11` 那条：**指标只能细化口径，不能降低标准。**
> 方案一之所以更好，就是因为它一条都没降，只是把"用哪个骨干"这个前置条件写清楚了。

## 五、答辩问答预案（把最容易被问倒的问题提前想清楚）

| 追问 | 建议应答口径 | ⚠️ 不要这样说 |
|---|---|---|
| **之前的训练为什么训不起来？现在凭什么能？** | **这是最可能被问、也最能体现工作深度的一问。** 答："我们把根因定位为**骨干随机初始化**——没有预训练权重的 ViT 在几千张图上无法建立判决边界。我们做了**受控对照实验**（附件 A8）：两臂除 `backbone_weights` 外完全一致（过滤注释后只剩实验标签与落盘路径两处无关差异）。**判据不是准确率，而是混淆矩阵里 `tn` 和 `tp` 是否同时为正**：随机初始化臂 `tn=0`，把全部样本判成伪造，判决边界根本不存在；预训练臂 `tn=163 / tp=582`，两类都能判对，边界建立起来了。**同时我们如实说明**：两臂 AUC 只差 +0.038，差距不算大，所以我们的结论是'预训练权重是边界能建立的**必要条件**，远非充分条件'——要到申报指标还得靠完整三阶段训练 + 官方 70 GB 训练集 + GPU。" | ①说"调参调好了"或"换了个学习率"（把工程问题说成玄学）；②声称"预训练权重决定性地提升了性能"——两臂 AUC 只差 0.038，这么说会被抓；③把 s16 随机跑的 0.49~0.52 和 b16 随机跑的 0.64 混成一条结论 |
| 模型体积和精度怎么平衡？ | 给两档：轻量档 s16 体积 98.7 MB / 9.46~11.22 张每秒钟；高精度档 b16 体积 362.1 MB 需 INT8 压缩到 92.9 MB。**两档都做了实测**，见附件 A1~A3 | 含糊说"我们的模型很小很快" |
| 相位到底比幅值重要多少？ | "已查证公开文献只有定性结论（相位携带结构信息更关键，Oppenheim & Lim 1981），没有 1.7 倍这个定量出处。**我们正在用消融实验实测这个比值**，论文里将用实测值替换。" | 继续引用 1.7 倍说不出来源 |
| **"你们的 mIoU 是怎么算的？"** | **这是定位指标最容易被追问、也最容易翻车的一问。** 答："mIoU 至少有三种定义，同一模型能差一倍以上，所以我们**三种都算、都报，并明确写明判定用的是哪一个**：① 池化（全局像素汇总，按像素加权，最宽松，只用于看训练趋势）；② **仅篡改图（含篡改区域的图逐图平均）——这是 ManTra-Net / SPAN / CAT-Net 等的可比口径，我们论文报这个，也是达标判定口径**；③ 全部非空图（额外把误报的真实图记 IoU=0，最严格）。三种口径的定义我们用 `scripts/test_metric_definitions.py` 以手算样例做了回归测试钉死，改实现就会报警。" | ①只报最高的那个池化值；②以为"池化偏高是因为真实图全零掩码按 IoU=1 计入"——**这是错的**，全零图是被跳过的，真实原因按像素加权（见 `docs/09` §4.4）；③三处文档各报一个口径却不标注 |
| **"AP 是怎么算的？为什么不是 11 点插值？"** | **这一问的诚实回答能直接体现方法严谨性。** 答："我们报的 AP 是 Σ(Rₙ−Rₙ₋₁)·Pₙ，且**按不同分数值分组**再积分——因为 PR 曲线的一个点对应**一个阈值**，并列分数共用一个阈值。我们用三条边界对拍把定义钉死：**完美可分 = 1.0、分数全同时 = 正类占比**（这是我们退化臂的实际情况，全同分时若按逐正例求和会得到 0.3118，正确答案是 0.5）。AUC 同理必须是**并列秩平均**版，全同分时为 0.5，不做校正的梯形法会给 0.0——**而低估退化臂反而会放大我们自己的对照优势，方向对我们有利，所以更不能含糊**。这两个指标全仓库只有 `src/engine/metrics.py` 一处实现，并有'三处入口必须逐位一致'的回归断言。" | ①报 11 点插值却说是"标准 AP"（11 点是已弃用的 VOC2007 粗粒度近似，完美可分也只是 1.0 但中间差别可达 0.09）；②同一份材料里主实验表用一个口径、跨生成器表用另一个口径；③在退化模型上引用它的 AP/AUC 却不说明并列处理的后果 |
| 数据量够吗？ | 分三层答：① ForenSynths **test 已完整清点，90329 张 / 13 生成器**（官方 90310，吻合）；② val 20 类 8000 张；③ train 70.4 GB 下载中，**若最终只用 4 类子集会明确写明训练集范围**。 | 说"约 10 万张"（错的，见 `docs/02`）；或声称"在 ForenSynths 全量上训练"而实际用子集 |
| 跨生成器泛化做过吗？ | "已完成同生成器留出验证，跨生成器评估的多生成器测试集**已下载完整**，待正式训练出权重后即可评测"——**必须区分这两个概念**，并且逐生成器指标必须用分层采样脚本 `eval_cross_generator.py` 出，不能用按 max_samples 抽样的 `evaluate.py` | 把同生成器结果说成跨生成器 |
| 为什么用 VIB？ | 抑制纹理细节带来的过拟合；且**频域 + VIB 两个创新模块合计只占 0.8% 参数**，几乎零成本 | 只说"提升了效果"而不给参数量证据 |
| INT8 量化后更快吗？ | "本机 CPU 缺少 VNNI 指令，INT8 反而变慢（298.6 ms vs 105.7 ms）。所以 INT8 在本项目中的定位是**压缩体积**，速度收益取决于目标平台指令集。" | 笼统说"量化后推理更快" |
| 大模型时代/CLIP 权重是从 HF 下的吗？ | 如实说：受限网络下 CLIP 权重未取得，对照实验用了 **ImageNet-1K 预训练 ViT-B/16**（同为 ViT-B/16 结构）作为替代，代码支持三条加载路径（本地 CLIP 目录 → HF 名称 → 兜底骨干+本地权重），拿到 CLIP 后无需改代码即可切换 | 把替代骨干的结果说成"验证了 CLIP 语义先验" |
| 一个人做得完吗？ | 用 `docs/10` 的止损规则回答：核心必做项已锁定，非核心项按优先级砍 | 承诺全部做完 |
