## 一、三步走部署链路

```
PyTorch 权重 (.pt)
   │  ① 导出 + 简化
   ▼
ONNX (.onnx)          opset 17, do_constant_folding, export_params
   │  ② OpenVINO 转换
   ▼
OpenVINO IR (.xml/.bin)
   │  ③ NNCF INT8 量化（★ 决定能否满足 ≤120MB）
   ▼
部署模型（桌面工具加载）
```

### ① 导出 ONNX

```bash
python -m src.deploy.export_onnx \
    --ckpt checkpoints/vibnet_best.pt \
    --out deploy/vibnet.onnx \
    --opset 17 --simplify
```

**导出脚本自动做了两件关键的事：**

1. **把 VIB 切到确定性路径**（`sample_vib=False`，取 μ）。
   否则每次推理结果都会抖动，桌面工具会出现"同一张图两次结果不同"的 bug。
2. **把频域分支的 DFT 从 `torch.fft` 切到 matmul 实现**（`model.set_dft_mode("matmul")`）。
   PyTorch 的 `aten::fft_fft2` **无法导出到 opset 17**，
   不切就会直接报 `UnsupportedOperatorError`。详见 `src/models/dft.py` 顶部注释。

**导出后会自动校验：** `onnx.checker.check_model()` + `onnxruntime` 跑一次真实推理。

### ② 转 OpenVINO IR + 测速

```bash
python -m src.deploy.optimize_openvino \
    --onnx deploy/vibnet_simplified.onnx \
    --out deploy/vibnet_ir --bench
```

输出 `deploy/benchmark.json`，包含 ONNXRuntime 与 OpenVINO 两条路径的
`fps` / `latency_ms` / `size_mb`，并自动判定是否达标：

```json
{
  "check": {
    "CPU_fps": 12.4,
    "target_fps>=8": true,
    "size_mb": 90.2,
    "target_size<=120MB": true
  }
}
```

**命令行等价做法（申报书里写的原版工具）：**
```bash
mo --input_model deploy/vibnet.onnx --output_dir deploy/vibnet_ir
benchmark_app -m deploy/vibnet_ir/vibnet.xml -d CPU -api async
```

### ③ INT8 量化（**这一步决定体积指标能否达标**）

```bash
python -m src.deploy.optimize_openvino \
    --onnx deploy/vibnet_simplified.onnx \
    --out deploy/vibnet_ir_int8 --int8
```

需要 `pip install nncf`，以及 100~300 张校准图放在 `data/` 下
（**真实与伪造各半最好**，只用真图校准会让量化偏向真实分布）。

| 精度 | 全模型体积（CLIP-ViT-B/16 骨干） | 是否达标 |
|---|---|---|
| FP32 | ≈363 MB | ❌ |
| FP16 | ≈182 MB | ❌ |
| **INT8** | **≈91 MB** | ✅ |

> **顺序很重要：先转 IR 再量化**，不要跳过 `onnxsim`（简化能去掉冗余算子，
> 让量化后的精度损失更小）。
>
> **量化后必须重新评测！** INT8 通常掉 0.3~1 个点 ACC，
> 如果掉超过 2 个点，检查：① 校准集是否覆盖了测试分布；② 是否用了 `--fp16` 混合精度；
> ③ 敏感层（如 DFT 的 matmul）是否需要保留 FP32。

## 二、桌面工具（PyQt5）

```bash
python app/main.py
```

### 界面与模块对应

```
┌───────────── 工具栏：开始检测 / 停止 / 导出 PDF / 导出掩码 / 批量导出 / 重新加载模型 ─────────────┐
│ ┌──────────────────────┐  ┌──────────────────────────────────────────────────────┐ │
│ │ ① 图像输入            │  │ ③ 结果展示（Tab1 详细视图）                            │ │
│ │  - 上传单张/批量/文件夹 │  │   ┌────────┬────────┬──────────┐                   │ │
│ │  - 拖拽上传            │  │   │ 原始图像 │ 热力图  │ 检测报告  │                   │ │
│ │  - 支持中文路径        │  │   └────────┴────────┴──────────┘                   │ │
│ ├──────────────────────┤  │  Tab2 批量结果表格（可点击回看）                        │ │
│ │ ⑤ 系统设置            │  │                                                      │ │
│ │  - 推理后端/设备       │  │                                                      │ │
│ │  - 检测阈值            │  │                                                      │ │
│ │  - 保存路径/模型路径   │  │                                                      │ │
│ └──────────────────────┘  └──────────────────────────────────────────────────────┘ │
├────────────────────── 进度条 + 状态栏 ──────────────────────────────────────────────┤
└─────────────────────────────────────────────────────────────────────────────────────┘
```

### 模块文件对应

| 模块 | 文件 | 关键实现 |
|---|---|---|
| ① 图像输入 | `app/modules/input_panel.py` | `ThumbListWidget` 支持拖拽；`collect_images()` 递归遍历文件夹；中文路径兜底 |
| ② 检测处理 | `app/modules/workers.py` | `DetectorLoader`（后台加载模型）+ `BatchDetectWorker`（异步批量推理，可中断） |
| ③ 结果展示 | `app/modules/result_panel.py` | `ImageView` 自适应缩放；三栏 `QSplitter`；批量表格点击回看 |
| ④ 结果导出 | `app/modules/exporter.py` | PDF 用 QtPrintSupport（零依赖），回退 reportlab；掩码 PNG 白=篡改 |
| ⑤ 系统设置 | `app/modules/settings_panel.py` | `QSettings` 持久化；后端下拉框自动探测已安装的推理框架 |

### 三种推理后端

`src/deploy/inference.py` 的 `Detector` 统一封装，桌面工具通过下拉框切换：

| 后端 | 加载什么 | 适用场景 |
|---|---|---|
| `torch` | `checkpoints/*.pt` | 开发调试、精度核对 |
| `onnx` | `deploy/*.onnx` | 通用部署，装机最简单（只需 onnxruntime） |
| `openvino` | `deploy/*_ir/*.xml` | **Intel CPU 上最快，推荐给最终用户** |

**三者结果必须一致**（数值上可能有 1e-3 级差异，这是正常的）。
自测方法：同一张图分别用三种后端跑，比较 `prob_fake`。

### 完全离线的保证

- 工具启动时**不访问任何网络**（模型从本地文件加载）；
- 权重不下载、不上传；图像不经过任何服务；
- 唯一的网络行为是加载 CLIP 权重（**训练阶段**的事），部署模型是自包含的 `.xml/.bin`。

> 这一点在申报书里是卖点（"保障用户隐私安全"），
> **演示时可以把网线拔掉给对方看**，效果很好。

## 三、打包成免安装 exe

```bash
pip install pyinstaller

pyinstaller -w -F --name "VIB-Net检测工具" app/main.py \
  --add-data "configs;configs" \
  --add-data "deploy/vibnet_ir;deploy/vibnet_ir" \
  --collect-all PyQt5 \
  --collect-all openvino \
  --collect-data certifi
```

**打包的三个大坑：**

1. **必须 `--collect-all`** 带上 `PyQt5` / `openvino`（如果还要 torch 后端，再加 `torch`），
   否则运行时报缺 DLL。打包后体积会到 500MB+，**这是正常的**（含推理运行时）。
2. **路径问题**：`app/main.py` 里已经用 `os.path.dirname(os.path.dirname(__file__))` 定位项目根目录，
   但 PyInstaller 打包后 `__file__` 的行为不同。如果启动后找不到 `configs/`，
   在 `main.py` 顶部加：
   ```python
   import sys, os
   ROOT = getattr(sys, "_MEIPASS", os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
   ```
3. **杀软误报**：PyInstaller 单文件打包常被 Windows Defender 拦。
   演示前一小时先跑一遍，把 exe 加入白名单；或者用 `-D`（文件夹模式）代替 `-F`。

**更省事的方案：** 直接发 `python app/main.py` + 一份 `启动.bat`：
```bat
@echo off
cd /d %~dp0
.venv\Scripts\python.exe app\main.py
```
配合一个打包好的 `.venv` 目录，简单可靠，不会杀软误报。

## 四、部署性能优化清单

如果 CPU 吞吐达不到 8 张/秒，按下面的顺序优化：

| 顺序 | 手段 | 预期收益 | 代价 |
|---|---|---|---|
| 1 | **INT8 量化** | 1.5~2.5× | ACC 掉 0.3~1 点 |
| 2 | 用 `openvino` 后端而不是 `onnx` 后端 | 1.3~2× | 需要装 openvino |
| 3 | 降低输入分辨率（224 → 192） | 1.4× | 定位精度下降 |
| 4 | 减少频域分支 DFT 的开销 | 视实现 | 需要重新设计 |
| 5 | 把 matmul-DFT 换成 ONNX 原生 `DFT` 算子 | 视后端 | 需要自己写符号函数 |
| 6 | 线程数调优（`ov.Core()` + `set_property`） | 1.1~1.3× | 简单，先做这个 |
| 7 | 换更小的 CLIP 骨干（MobileCLIP/TinyCLIP） | 2~5× | 需要重新训练验证 |

**线程数调优示例：**
```python
import openvino as ov
core = ov.Core()
core.set_property("CPU", {"INFERENCE_NUM_THREADS": 4,
                          "PERFORMANCE_HINT": "THROUGHPUT"})
compiled = core.compile_model(model, "CPU")
```

> **实测参考（本机 i7，轻量兜底骨干 33.8M）：**
> ONNXRuntime 0.24 张/秒、OpenVINO 1.5 张/秒。
> 这个数字**远低于** 8 张/秒 —— 主要瓶颈是 matmul-DFT（6 次 224×224 矩阵乘法）
> 和兜底骨干的注意力块。
> **换成真正的 CLIP + INT8 量化 + 线程调优后，需要实测确认能否达标。**
> 如果达不到，最有效的办法是第 3 条（降分辨率）和第 6 条（线程调优）。

## 五、部署阶段自检清单

- [ ] `ontnx.checker` 与 `onnxruntime` 推理校验通过
- [ ] ONNX → IR 转换成功，`deploy/vibnet_ir/vibnet.xml` 存在
- [ ] INT8 量化后模型存在，且**体积 ≤120MB**
- [ ] `benchmark.json` 里 `CPU_fps ≥ 8`
- [ ] `torch` / `onnx` / `openvino` 三种后端在同一张图上的 `prob_fake` 差异 <1e-3
- [ ] 桌面工具五大模块功能逐项自测通过（见下表）
- [ ] 拔掉网线，工具仍能正常检测（完全离线）
- [ ] 中文路径、中文文件名的图像能正常读写
- [ ] PDF 报告能打开，中文不乱码
- [ ] 掩码 PNG：白色区域 = 篡改区域（用画图打开肉眼确认）
- [ ] 批量检测 100 张时界面不卡顿、进度条正常推进
- [ ] 中途点"停止"能真正停下来，且已检测的结果保留
- [ ] 打包成 exe 后能在**另一台没装 Python 的电脑**上运行
