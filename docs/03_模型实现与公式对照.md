> ⚠️ **读代码时必看：损失项的命名与直觉不一致。**
> 申报书公式把四项写成 `L_VIB / L_BCE / L_Dice / L_edge`，容易让人以为
> `L_BCE` 是**分类**的二值交叉熵。实际上：
>
> | 日志/raw 里的键 | 真实含义 | 代码位置 |
> |---|---|---|
> | `vib` | **分类**损失 `CE(cls_logits, labels) + β·KL` | `multi_task.vib_loss` |
> | `bce` | **定位**损失的逐像素 BCE（不是分类 BCE） | `multi_task.bce_loss` |
> | `dice` | 掩码 Dice（定位） | `multi_task.dice_loss` |
> | `edge` | 边缘 BCE（定位） | `multi_task.edge_loss` |
>
> 也就是说**分类的交叉熵被并进了 `vib` 这一项**，而 `bce` 只在有 GT 掩码的
> 定位阶段才出现。后果是：
> - 只跑分类阶段（`use_tasks: ["cls"]`）时，日志里只会看到 `raw={'vib': ...}`，
>   **不代表分类没在训**，`vib` 里就包含交叉熵；
> - 论文/答辩讲损失时，不要照着键名说"BCE 是分类损失"，会被问住。
>
> 建议后续统一改名为 `cls / mask_bce / dice / edge`，让键名自解释。

**参数规模（实测，轻量兜底骨干）：**

## 二、五个关键实现点（不看会踩坑）

### 2.1 空域特征的"向量 vs 特征图"统一

**问题**：公式 (1)(3) 写的是向量，1.3(3) 要求 14×14×512 的特征图。
直接把 896 维向量做 1×1 卷积，空间分辨率是 1×1，**定位支路上采样不出任何空间信息**。

**实现**：同时保留两种形式（`spatial_branch.py`）

```python
cls_token, patch_map = backbone(x)      # (B,768) 和 (B,768,14,14)
local_map = local_texture(x)            # (B,128,14,14)
f_spa = torch.cat([patch_map, local_map], dim=1)   # (B,896,14,14)
# 对 f_spa 做 mean(dim=(2,3)) 就得到公式 (3) 的 896 维向量
```

- CLS token → 公式 (1) 的全局语义向量（用于分类支路的语义描述）
- patch token 重排 → 14×14×768 的空间特征图（供定位支路使用）

### 2.2 频域分支：**PyTorch 的 FFT 无法导出 ONNX**

**这是本项目最隐蔽、后果最严重的坑。**

```python
# 写在模型里最自然，但：
spec = torch.fft.fft2(x)
# torch.onnx.export(..., opset_version=17) ->
# UnsupportedOperatorError: Exporting the operator 'aten::fft_fft2' to
# ONNX opset version 17 is not supported
```

PyTorch **没有**为 `fft_fft2` 注册 ONNX 符号函数，所以模型**根本导不出 ONNX**，
后面 OpenVINO 加速、桌面工具全部卡死。这个问题通常到项目后期（部署阶段）才暴露，
届时已经来不及改结构。

**实现**（`src/models/dft.py`）：把 2D-DFT 写成**固定矩阵乘法**

```
F = W_H · x · W_W^T
Re(F) = (Wre_H·x)·Wre_W^T − (Wim_H·x)·Wim_W^T
Im(F) = (Wre_H·x)·Wim_W^T + (Wim_H·x)·Wre_W^T
```

- `fftshift` **烘焙进行序**（行索引 `(h + H//2) % H`），省掉一次 roll 操作；
- 全程只有 matmul / sqrt / atan2 —— 全部是 opset 17 支持的算子；
- 数值等价性已验证：幅值最大误差 1.8e-6，相位最大圆周误差 4.4e-5；
- 计算量约 67M MAC/张，Intel i7 上约 1~3 ms，**比未优化的 FFT 算子更可控**。

**用法**：
```python
model.set_dft_mode("torch")    # 训练（GPU 上 FFT 更快）
model.set_dft_mode("matmul")   # 导出前（export_onnx.py 会自动调用）
```

**这个发现建议写进论文的"工程实现"部分** —— 它解释了为什么模型能真正落地。

### 2.3 可学习频域掩码的输入要先做对数压缩

幅值谱动态范围极大（1e-3 ~ 1e3），直接送进掩码网络，Sigmoid 会被少数高频点主导，
学出来的掩码要么全 0 要么全 1（退化）。

```python
log_amp = torch.log1p(amp)      # ★ 先对数压缩
mask = self.mask_net(log_amp)
```

**验证掩码是否退化：** 训练后把 `mask[0,0]` 画出来，
健康的掩码应该有**明显的空间结构**（环带/块状），而不是一片均匀灰度。
如果退化了：① 确认用了 `log1p`；② 给掩码加 L1 稀疏约束；
③ 把掩码网络的学习率单独调低。

### 2.4 分层 VIB：两个致命细节

#### (a) σ 的初始化必须让 KL 从 0 起步

`KL(N(μ,σ²)‖N(0,1)) = 0.5·Σ(μ² + σ² − log σ² − 1)`

| σ 初值 | 初始 KL（256 维） | 后果 |
|---|---|---|
| 0.1（错误） | ≈137 | 一上来就被裁到 10，**梯度被 clamp 吃掉，VIB 完全不工作** |
| **1.0（正确）** | **≈0** | KL 从 0 平稳增长，瓶颈逐步生效 |

实现：`Softplus(b) = 1  ⇒  b = log(e − 1) ≈ 0.5413`

```python
nn.init.constant_(self.fc_sigma.bias, math.log(math.e - 1.0))   # σ(0) ≈ 1
```

#### (b) KL 裁剪不能杀掉梯度

`torch.clamp` 在区间外**梯度为 0**。如果 KL 常态性地 > 10，
公式 (25) 就会把 VIB 正则项变成"常数"—— **等于静默关闭信息瓶颈**，
而且从训练日志上完全看不出来。

**实现**：前向仍然硬裁剪（满足公式 (25) 的数值语义），反向按恒等传递：

```python
clipped = torch.clamp(kl, lo, hi)
if grad_through:
    clipped = kl + (clipped - kl).detach()   # 前向=clipped，反向=1
```

同时提供两种 KL 归约口径：

| `kl_reduction` | 数值范围 | 说明 |
|---|---|---|
| `mean`（默认） | 0.0x ~ 几 | 对 batch 和 latent 维都取均值，此时 [0,10] 是**安全阀**而非常态 |
| `sum` | 几十 ~ 几百 | Alemi 原始 VIB 写法，此时 [0,10] 会**常态触发**，需配合 `grad_through` |

**训练时监控 KL 曲线**：健康 = 缓慢上升后趋于平稳；危险 = 一直涨（瓶颈失效）
或直接掉到 0（后验坍缩）。

### 2.5 Canny 边缘提取的 epsilon 陷阱

```python
# ❌ 错误写法
mag = torch.sqrt(gx**2 + gy**2 + 1e-8)
mag = mag / (mag.amax(dim=(2,3), keepdim=True) + 1e-8)
```

**后果**：全零掩码时 `mag ≡ 1e-4`、`amax = 1e-4`，归一化后 `mag ≡ 1.0`
→ **整幅图都被判成边缘**！边缘监督会教模型"到处都有边缘"。

```python
# ✓ 正确写法
mag = torch.sqrt(gx**2 + gy**2)                                # eps 不要放 sqrt 里
scale = mag.amax(dim=(2,3), keepdim=True).clamp_min(1e-6)
mag = mag / scale
```

**这个 bug 藏得很深**（只在全零掩码时暴露），但会静默地把边缘分支废掉。
本仓库的 `smoke_test.py` 专门有一项检查它：全零掩码的边缘像素数必须为 0。

## 三、消融开关一览

所有消融项都通过配置切换，**不需要改代码**（`src/evaluation/ablation.py` 的 `ABLATION_PRESETS`）：

| 消融项 | 配置覆盖 | 影响的模块 |
|---|---|---|
| `full` | — | 完整模型 |
| `no_learnable_mask` | `model.freq.use_learnable_mask: false` | 可学习掩码 → 固定中频环形掩码 |
| `no_phase` | `model.freq.use_phase: false` | 去掉相位支路（F_freq 从 256→128 维） |
| `no_cross_attention` | `model.fusion.use_cross_attention: false` | CS-CAM → 1×1 卷积后直接相加 |
| `no_vib` | `model.vib.use_vib: false` | 去掉 VIB，分类支路直接用 F_fusion 的 GAP |
| `no_grad_stop` | `model.localization.use_grad_stop: false` | 去掉梯度停止层 |
| `no_edge` | `model.localization.use_edge_head: false` | 去掉 Canny 边缘监督分支 |

**注意**：`use_phase: false` 时 `F_freq` 通道数变成 128，CS-CAM 会自动适配
（`spatial_branch.out_dim` / `freq_branch.out_dim` 是动态计算的）。

## 四、模块自检 API

每个模块都提供 `sanity_check()`，用于快速核对维度：

```python
from src.models.vibnet import build_model, load_config
cfg = load_config("configs/default.yaml")
model = build_model(cfg)

print(model.spatial.sanity_check())      # 公式 (1)(2)(3) 的维度
print(model.freq.sanity_check())         # 公式 (4)~(12) 的维度
print(model.fusion.sanity_check())       # 公式 (13)~(17) 的维度
print(model.vib.sanity_check())          # 公式 (20)~(25) 的维度 + β 分段值
print(model.localization.head)           # Mobile-UNetv2 结构
print(model.summary())                   # 各模块参数量

print(model.sanity_check())              # 端到端：全部公式维度一次核对
```
