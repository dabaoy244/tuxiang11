## 一、指标口径（必须先统一，否则数据全部作废）

### 真伪检测（整图二分类，正类 = 伪造）

| 指标 | 实现 | 说明 |
|---|---|---|
| ACC | `src/engine/metrics.py: ClassificationMetrics` | 阈值 0.5 |
| Precision / Recall / F1 | 同上 | 阈值 0.5 |
| AUC | `src.engine.metrics.roc_auc`（**全仓库唯一实现**） | Mann–Whitney U / **秩平均**。分数有并列时必须用秩平均；不做校正的梯形法在同分上给 0.0（错），另存 `auc_trapz` 仅作对照 |
| AP | `src.engine.metrics.average_precision`（**全仓库唯一实现**） | Σ (Rₙ−Rₙ₋₁)·Pₙ，**按不同分数值分组**（VOC2010+ / COCO 口径）。完美可分 = 1.0；**分数全同时 = 正类占比** |

> ⚠ **两个指标都只能从 `src/engine/metrics.py` 取，不要在脚本里再抄一份。**
> 本项目曾经踩过：`src/engine/metrics.py` 与 `scripts/eval_cross_generator.py`
> **各有一份 AUC/AP 实现**，同名字段 `ap` 下是两套不同定义（11 点插值 vs 逐正例求和），
> 导致主实验表与跨生成器表的数字**不可比**。现在口径唯一，
> 由 `scripts/test_metric_definitions.py` 的"跨入口一致性"断言守住。

> ⚠ **AUC / AP 的边界必须对拍**：完美可分 → 1.0、完全反向 → 0.0（AUC）、
> **全同分 → 0.5（AUC）与 → 正类占比（AP）**。
> 退化模型常整批输出饱和同分（全 0.0 或全 1.0），不做并列校正会把它的分数
> **系统性压低**，反而放大对照实验的优势 —— 这是"朝自己有利方向偏"的错误。
> 由 `scripts/test_metric_definitions.py` 的 B 部分钉死。

> ⚠ **ACC / F1 在退化模型上不可用**：正类占比 `p` 固定时，恒判假的 ACC 恒为
> `1-p`、F1 恒为 0，**与模型无关**。判定"模型是否真的学到边界"要看混淆矩阵
> `tn` / `tp` 是否同时为正，见 `docs/14` §4.2。

### 篡改定位（像素级）

| 指标 | 说明 |
|---|---|
| mIoU（池化） | 全数据集像素级 IoU = TP/(TP+FP+FN)，**按像素加权、最宽松，只用于看训练趋势** |
| mIoU `miou_tampered_only` | 仅含篡改区域的图逐图平均，**★这是论文与达标判定的口径**，与 ManTra-Net / SPAN / CAT-Net 可比 |
| mIoU `miou_per_sample` | 全部非空图逐图平均（含被误报的真实图，记 IoU=0），**更严格**，用于误报代价分析 |
| Pixel Acc | (TP+TN)/全部像素，**会被背景主导**，参考价值有限 |
| Dice | 2TP/(2TP+FP+FN) |

> ⚠ **报告 mIoU 时务必注明是哪种口径 —— 本仓库同时算三种，能差一倍以上。**
> 很多论文含糊其辞，答辩时会被追问。`evaluate.py` 三种并列输出：
>
> | 口径 | 字段 | 定义 | 用途 |
> |---|---|---|---|
> | ① 池化（最宽松） | `miou` | 全局像素汇总后 `tp/(tp+fp+fn)`，**按像素加权** | 只看训练趋势 |
> | ② **仅篡改图（★判定用）** | `miou_tampered_only` | 只在 GT 含篡改区域的图上逐图平均 | **论文报这个**，与 ManTra-Net / SPAN / CAT-Net 可比 |
> | ③ 全部非空图（最严格） | `miou_per_sample` | 含被误报的真实图（记 IoU=0） | 误报代价敏感性分析 |
>
> 三者定义由 `scripts/test_metric_definitions.py` 用手算样例做回归测试钉死。
> 详见 `docs/09` §4.4。

### 推理性能

| 指标 | 获取方式 |
|---|---|
| CPU 推理速度（张/秒） | `python -m src.deploy.optimize_openvino --bench` |
| GPU 推理速度 | 把 `benchmark()` 的 `device` 参数改成 `"GPU"` |
| 模型体积（MB） | `--size-only --params-m <参数量>` 或直接看文件大小 |

> **测速要规范：** 先 warmup（≥5 次）再计时，取 50 次平均；
> 明确 batch=1 还是 batch=N（申报书写的是 224×224，通常指 batch=1）；
> 明确是否含预处理（缩放/归一化）。**本仓库的 `latency_ms` 只算模型前向，不含图像读写。**

## 三、鲁棒性测试（本项目的重要卖点）

```bash
python -m src.evaluation.robustness --ckpt checkpoints/vibnet_best.pt --max-samples 2000
```

输出 `outputs/robustness.json` + `robustness.md`（Markdown 表格，直接贴论文）。

**覆盖 21 种后处理：**

| 类别 | 参数 |
|---|---|
| JPEG 压缩 | q = 10, 20, 30, 50, 70, 90 |
| 缩放 | 0.5, 0.75, 1.25, 1.5, 2.0（缩完再还原到原尺寸再评测） |
| 裁剪 | 随机裁掉 10%, 20%, 30%, 40%, 50% 后还原 |
| 旋转 | 0°, 90°, 180°, 270° |
| 高斯噪声 | σ = 0.01, 0.02, 0.05 |
| 椒盐噪声 | density = 0.01, 0.02, 0.05 |

**报告方式：** 除了绝对指标，**必须报"下降率"**（ΔACC / ΔmIoU 相对原图）。
申报书 6.3 明确要求"在不同后处理操作下的检测精度和定位精度下降率"。

**实验设计建议：**
- 至少跑 3 个随机种子，报 **均值 ± 标准差**（裁剪是随机的，单次结果不可复现）；
- 最有价值的对比是"本方法 vs BiHPF"在 JPEG q=10~30 下的表现 ——
  频域方法普遍在强压缩下崩得厉害，如果你的方法能扛住，这就是核心卖点；
- 画一张折线图：横轴 JPEG 质量因子，纵轴 ACC，两条线（本方法 / 基线）。

## 五、消融实验（最容易做错的一个）

```bash
# 错误的做法（只能验证"推理时关掉模块"的影响）
python -m src.evaluation.ablation --mode eval

# 正确的做法（每项独立训练）
python -m src.evaluation.ablation --mode train --epochs-scale 0.6
```

**消融项（7 项）：**

| 项 | 移除什么 | 验证的论点 |
|---|---|---|
| `full` | — | 基准 |
| `no_learnable_mask` | 可学习掩码 → 固定中频环带 | "自适应频率选择优于固定掩码" |
| `no_phase` | 相位支路 | "相位信息有独立贡献" |
| `no_cross_attention` | CS-CAM → 直接相加 | "注意力融合优于朴素相加" |
| `no_vib` | 分层 VIB | "信息瓶颈提升泛化性" |
| `no_grad_stop` | 梯度停止层 | "梯度隔离缓解任务冲突" |
| `no_edge` | Canny 边缘监督 | "边缘监督提升定位边缘精度" |

**报告要求：**
- 每一项都要有 **ΔACC 和 ΔmIoU**（这是消融表的灵魂）；
- 如果某项 Δ 小于 0.5%，**必须诚实报告并给解释**（例如"该模块主要在强压缩场景下有效，
  原始测试集上差异不显著"），或者干脆在论文里承认该模块贡献有限。
  **不要为了凑故事而隐藏无效的消融项** —— 这是学术诚信问题，审稿人也会自己复现。

## 六、结果可视化（论文图）

`src/deploy/inference.py` 的 `Detector.build_overlay()` 已经生成了热力图叠加图。
建议做一张**四列对比图**：

| 列 1 | 列 2 | 列 3 | 列 4 | 列 5 |
|---|---|---|---|---|
| 原始图像 | GT 掩码 | 本方法 | 基线（如 BiHPF） | 失败案例 |

**选图原则：**
- 至少包含 1 个**成功案例**和 1 个**失败案例**（只展示成功的显得不专业）；
- 失败案例要给出分析（例如"目标区域过小（<1% 面积）导致漏检"）；
- 覆盖不同篡改类型：拼接、复制移动、AI 生成。

**另一张必画的图：可学习频域掩码的可视化**
把 `mask[0,0]` 用 `viridis` 画出来，旁边放固定中频掩码做对比。
这张图能一眼看出"模型自动学到了非中频结构"，是全篇最有说服力的一张。

## 七、统计显著性（加分项）

如果要做强论证，建议对主指标做显著性检验：

- 跑 **3~5 个随机种子**，报告 `均值 ± 标准差`；
- 与基线的对比用**配对 t 检验**或 **McNemar 检验**（分类）、**Wilcoxon 符号秩检验**（IoU）；
- p < 0.05 才可以说"显著优于"。

> 做到这一步，论文的档次会明显提升。CASIA v2 只有 100~8412 张，
> 单次实验的 1~2 个点差异很可能只是随机波动。

- [x] 测试集与训练集**无重叠**（按图像内容/来源检查，不只是文件名）
  → ⚠ **2026-09-19 实测：此项不成立，已据实修正口径。**
  审计脚本 `scripts/audit_train_eval_overlap.py`（按 MD5 比对，**不看文件名**）结果：
  * **池级**：训练池 `val` 的真图有 **400 / 4000（10%）**与 `test` 池内图像
    **逐字节相同**，且高度集中 —— `cat` **200/200**、`horse` **200/200** 是整类命中；
    其余 18 类内容零重叠（`car` 有 22 个**同名但不同图**，属索引撞名，不计入）。
  * **实际用到的子集**：`train 1600 ∩ eval 1300` 命中 **3 张**（0.23%），
    `train 1600 ∩ 跨生成器评测计划 2600` 也命中 **3 张**。
  * 结论口径：**只能说"本次子采样实测重叠 3 张"，不能写"无交集"**；
    风险在于**扩大评测规模**——池级那 400 张会按比例进来。
  * 去泄漏机制：`audit_train_eval_overlap.py --pool --write-exclude <清单>` 生成
    评测侧的排除清单，再用 `eval_cross_generator.py --exclude-list <清单>` 重算
    （清单在**挑选之前**剔除候选，因此不降低 `--per-class` 的取数）。
