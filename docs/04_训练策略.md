# 04 · 训练策略与调参

## 一、三阶段训练（申报书 1.4(3) 的落地）

```bash
python scripts/train.py --config configs/default.yaml
```

配置在 `configs/default.yaml` 的 `train.stages`：

| 阶段 | epoch | 冻结 | 训练 | lr | lr 终点 | 任务 |
|---|---|---|---|---|---|---|
| ① 分类预训练 | 0–20 | `localization` | `spatial, freq, fusion, vib, cls_head` | 1e-4 | 1e-6 | cls |
| ② 定位预训练 | 20–40 | `vib, cls_head` | `spatial, freq, fusion, localization` | 5e-5 | 5e-7 | loc, edge |
| ③ 联合微调 | 40–70 | 无 | 全部 | 1e-5 | 1e-7 | cls, loc, edge |

优化器统一 AdamW，权重衰减 1e-5，余弦退火，**梯度 L2 范数裁剪到 5.0**（申报书 1.2(3)）。

### 为什么必须分阶段？

分类任务想要**抽象、压缩**的特征（提升泛化性），
定位任务想要**保留空间细节**的特征（提升细粒度）。

端到端一起训练时，两者会互相拉扯：
- 定位损失量级小（BCE ~1e-3），被分类损失（~1.0）直接淹没；
- 共享的 `F_fusion` 被两个方向相反的梯度同时更新，最终两边都不讨好。

分阶段 = **先各自充分收敛，再小心地联合微调**。
`beta_epoch_offset: 20` 让 β 退火在阶段三开始时从 t=20 续接（β 从 0 开始升到 0.1）。

### 每个阶段在看什么

**阶段一：** 关注 `raw={'vib': ...}` 和验证集的 `cls_acc`。
如果 20 轮内 cls_acc 还在 0.5 附近，先别往下走 —— 检查数据、CLIP 冻结策略、学习率。

**阶段二：** 关注 `raw={'bce','dice','edge'}` 和验证集 `loc_miou`。
mIoU 从 0 涨到 0.2 以上才算"学进去了"。

**阶段三：** 关注 `weights={'sigma_*'}` 的演化 —— **这是论文要用的一张图**。
四个 σ 会自动分化（有的升有的降），这就是"自动权重分配"的证据。

## 二、损失函数与权重

### 四个损失项

| 损失 | 量级（典型） | 说明 |
|---|---|---|
| `vib`（CE + β·KL） | ~0.7 | 分类主损失 |
| `bce`（定位 BCE） | ~1e-3 ~ 0.7 | 逐像素，小目标时量级很小 |
| `dice` | ~0.1 ~ 0.7 | 缓解前景/背景不均衡 |
| `edge`（边缘 BCE） | ~0.7 | 边缘监督 |

### Z-score 归一化（公式 30）

`L' = (L − μ_L) / σ_L`，μ/σ 取**过去 100 个批次**的滑动统计量。

实现要点：
- 统计量 **detach**（只让分子回传梯度），否则分母也会被优化、损失尺度失控；
- 窗口未满时用 EMA 兜底，保证第一步就能归一化；
- 某个损失项在当前阶段**从未被更新过**时（例如阶段一只训分类），
  退化为恒等归一化 (0, 1)，而不是报错 —— 否则第一次验证就会崩。

### 不确定性加权（公式 31）

```
L_total = 1/(2σ₁²)·L'_VIB + 1/(2σ₂²)·L'_BCE + 1/(2σ₃²)·L'_Dice + 1/(2σ₄²)·L'_Edge
          + log(σ₁σ₂σ₃σ₄)
```

数值稳定的等价写法（本仓库实现，无除法无开方、梯度有界）：

```python
s_i = log(σ_i²)                                    # 可学习参数，初始 0（σ=1，等权起步）
L_total = Σ [ 0.5·exp(-s_i)·L'_i + 0.5·s_i ]
```

**想看固定权重版本（消融基线）：** `loss.uncertainty_weighting: false`，
再用 `loss.weights` 指定固定权重。

### 常用调参对照

| 症状 | 调什么 | 怎么调 |
|---|---|---|
| 定位很糊、mIoU 低但 BCE 很低 | Dice 权重 | 关掉不确定性加权，手动把 `weights.dice` 调到 3.0 验证是否有效 |
| 分类泛化差 | β 上限 | `vib.beta_max` 从 0.1 提到 0.2~0.3（**注意 β 是 VIB 强度的核心旋钮**）|
| 训练不稳、loss 抖 | 学习率 / 梯度裁剪 | 阶段三 lr 从 1e-5 降到 5e-6；`grad_clip_norm` 从 5.0 降到 3.0 |
| 某个损失项一直主导 | 归一化窗口 | `zscore_window` 从 100 提到 200 |
| 显存不够 | batch / AMP | `train.batch_size` 降一半，同时把 lr 乘 0.7；或开 `train.amp: true` |

## 三、训练日志怎么读

`outputs/<run>/train_log.txt` 每行长这样：

```
[stage1_cls_pretrain] epoch 5/20 (global 4) lr=8.72e-05 beta=0.000 loss=-1.2345
  raw={'vib': 0.6342} (33.4s)
    val: cls_acc=0.7821  cls_auc=0.8402  cls_f1=0.7712  loss=-0.9812
    ✔ 新的最佳 val_total=-0.9812，已保存 best.pt
```

- `loss`：加权后的总损失（Z-score 归一化后可能为负，**这是正常的**，不要被吓到）；
- `raw=`：**未归一化的原始损失**，判断"模型到底学得怎么样"要看这个；
- `val:`：验证集指标；
- `weights=`（在 history.json 里）：四个 σ 的值，论文画图用。

数据结构化保存在 `outputs/<run>/history.json`，可以直接喂给 matplotlib 画曲线。

```python
import json, matplotlib.pyplot as plt
h = json.load(open("outputs/run_default/history.json"))
ep = [r["epoch"] for r in h]
plt.plot(ep, [r["train_raw"].get("vib") for r in h], label="vib")
plt.plot(ep, [r["train_raw"].get("bce") for r in h], label="bce")
plt.legend(); plt.xlabel("epoch"); plt.savefig("outputs/loss_curve.png", dpi=200)
```

### 必须画的三张图（论文用）

1. **损失曲线**：四个 raw loss 一起画，可见分阶段训练的"台阶"；
2. **σ 演化曲线**：证明不确定性加权真的在自动分配权重；
3. **KL 曲线**：`history.json` 里没有直接存，可从 `train_raw` 之外单独记录，
   或看 `beta` 与 `vib` loss 的关系推断。健康形态：缓慢上升后平稳。

## 四、快速实验套件（省时间）

```bash
# 只跑 5% 的轮数，验证代码改动是否可用（CPU 上几分钟）
python scripts/train.py --demo --epochs-scale 0.05

# 限制每个 epoch 的批次数，用于快速迭代
python scripts/train.py --demo --epochs-scale 0.1 --limit-batches 20

# 单阶段调试：只跑阶段三（用于调联合微调的超参）
# 编辑 configs 里的 stages 列表只留第三段，或新建一个 configs/joint_only.yaml
```

**建议的工作流：**
1. 用 `--demo --epochs-scale 0.05` 验证代码没写错；
2. 用**真实数据 + 10 轮**跑一个"小规模正式实验"，确认指标在往好的方向走；
3. 再放开 70 轮跑完整训练。

**不要一上来就跑 70 轮** —— 一次 1~2 天，跑完才发现数据划分有问题就白干了。

## 五、实验记录规范

每次实验必须记录（建议用一个 Excel 或 `experiments.csv`）：

| run_id | 时间 | 改动 | 阶段轮数 | batch | lr | β_max | val_acc | val_miou | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| r001 | 11-20 | baseline | 20/20/30 | 16 | 1e-4 | 0.1 | 0.872 | 0.412 | 全量数据 |
| r002 | 11-22 | β_max=0.3 | 20/20/30 | 16 | 1e-4 | 0.3 | 0.891 | 0.409 | 泛化↑定位↓ |

**只改一个变量**，否则说不清哪个改动起了作用。
`train.py --tag r002` 可以把权重命名区分开（`checkpoints/r002_best.pt`）。

## 六、常见失败模式速查

| 症状 | 可能原因 | 排查顺序 |
|---|---|---|
| loss 一直不降 | lr 太大 / 数据标签反了 / 冻结策略错了 | ① 打印一批数据的标签和掩码看看；② lr 降 10 倍试 |
| 定位输出全黑 | 混合批次掩码污染（`mask_valid` 丢了）/ Dice 权重太低 | ① 检查 `mask_valid`；② 看 `raw['dice']` 是否在降 |
| 定位输出全白 | BCE 被正样本主导 / 阈值不对 | ① 看 `raw['bce']`；② 提高 Dice 权重 |
| 分类 ACC 卡 50% | CLIP 前 6 层没冻结 / 数据泄漏（测试集混进训练集） | ① 检查 `freeze_first_n_layers`（**2026-09-26 前它不生效**，见 docs/08 D41）—— 判据是同一份日志里出现 `[阶段重放] 冻结前 6/12 层` 且`可训练参数 ≈47M / 总计 90.53M`；② 查 manifest 的划分 |
| 验证指标远好于训练 | 训练时开了太强的增强 / BN 统计问题 | ① 增强概率调低；② 检查冻结模块的 BN 是否处于 eval |
| KL 直接掉到 0 | 后验坍缩 | ① 降低 β；② 检查 σ 初始化 |
| KL 一直涨 | 瓶颈失效 | ① 提高 β；② 检查 KL 裁剪的反向梯度是否被 `clamp` 吃掉 |
| 训练到一半突然 NaN | 梯度爆炸 | ① 确认 `grad_clip_norm: 5.0` 生效；② 检查 `Softplus` 是否溢出 |
| 显存逐渐增长 | 保存了计算图 / 累积列表 | ① 确认 loss 用了 `.item()`；② 不要在主循环里堆 tensor |

## 七、算力预算参考

| 配置 | 单张 224×224 前向 | 70 轮（10 万张/轮）训练时间 |
|---|---|---|
| RTX 3090，FP32，batch 16 | ~25 ms | 约 12~18 小时 |
| RTX 4090，bf16，batch 32 | ~12 ms | 约 7~10 小时 |
| 单张 CPU（i7），batch 4 | ~1.4 s | 不现实，别试 |

**消融实验的算力账：** 7 个消融项 × 12~18 小时 ≈ **4~5 天连续占用**。
如果算力紧张：
- 把消融实验统一降到 40 轮（`--epochs-scale 0.6`），约 2~3 天；
- 或者先做完主实验，等论文审稿意见回来再补消融。

**这个账一定要在 2026 年 11 月之前算清楚并排好算力档期**，否则 2027 年 4 月会措手不及。
