> 面向"从没连过远程 Linux 服务器"的情况。读完这一页，你能自己登进那台

> 配套：`docs/18_AutoDL上云执行清单.md`（该跑哪些命令）、

## 0. 一句话结论

**你不需要会 Linux。** 三种进入方式任选一种，推荐 **JupyterLab** ——
在控制台点一个按钮，浏览器里就打开一个网页版 IDE，自带终端和文件管理器，
**零配置、不用记 IP、不用记密码**。

## 1. 先认清这台机器上有什么

### 三块盘（这是最要紧的一件事）

| 路径 | 是什么 | 大小 | 能放什么 |
|---|---|---|---|
| `/root` | **系统盘** | 30 GB | 代码可以放，但**装满就崩** |
| `/root/autodl-tmp` | **数据盘**（要扩容的是它） | 默认 50 GB，可扩 | **项目 + 数据集 + checkpoint 全放这里** |
| `/root/autodl-fs` | 同地区共享存储 | 20 GB 内免费 | 跨实例中转权重/结果 |

> 🔴 **铁律：所有东西都放 `/root/autodl-tmp`。**
> 一个 checkpoint 就有 362 MB，系统盘 30 GB 撑不了几轮，写满后
> 训练会以 `No space left on device` 崩掉，而且报错位置通常离真凶很远。

### 三个入口（都在控制台那一行里，见你截图）

| 入口 | 位置 | 适合 |
|---|---|---|
| **JupyterLab** | 快捷工具列 | ★ **推荐**，网页 IDE，带终端和文件管理 |
| **AutoPanel** | 快捷工具列 | 看 GPU 占用、端口、余额等概览 |
| **SSH** | SSH 登录列 | 长时间跑任务、本地脚本化操作 |
| 实例监控 | 快捷工具列 | 看 CPU/GPU/显存曲线 |

## 2. 入口 A：JupyterLab（推荐，零配置）

**步骤：**

1. 控制台实例列表 → 找到那台 `内蒙B区 / 089机` 的行 → 快捷工具列 → 点 **【JupyterLab】**
2. 浏览器新标签页打开，看到左边一列文件树、右边一块启动器面板
3. **打开终端**：点启动器里的 **Terminal**；或菜单 `File → New → Terminal`；
   也可以点文件树上方那个 **`+`** 再选 Terminal
4. 终端里**打字 → 回车**执行，跟本地命令行一样
5. **粘贴**：`Ctrl+Shift+V`，或者鼠标右键 → Paste
   （普通 `Ctrl+V` 在网页终端里常常不生效，这是最常见的新手卡点）

**JupyterLab 里能顺手做的事：**

- 上传：把文件**直接拖进**左侧文件树
- 下载：左侧文件上**右键 → Download**
- 看文件：双击文本文件直接编辑；图片直接预览
- 无卡模式下 **JupyterLab 一样能用**，只是没有 GPU —— 传数据、装环境照常

---

## 3. 入口 B：SSH（本地终端）

**步骤：**

1. 控制台 → SSH 登录列 → 点 **【登录指令】** 旁的复制图标
   → 得到形如 `ssh -p <端口> root@<主机名>` 的一整行
2. 同一行点 **【密码】** 旁的复制图标（记下这串密码）
3. 本地打开 **Git Bash**（你的默认 shell 就是它），**右键粘贴**登录指令 → 回车
   > 也可以用 Windows 自带的 PowerShell（Win10+ 自带 ssh）
4. 第一次连接会问 `Are you sure you want to continue connecting?` → 输 `yes` → 回车
5. 提示 `root@...'s password:` → **右键粘贴密码 → 回车**
   > ⚠️ **粘贴密码时屏幕上什么都不显示**，这是 Linux 的正常行为，不是没粘上。
   > 不要因为看不见就又粘一次（会被当成密码错误）。

<details>
<summary>连不上时按顺序查这四条</summary>

1. 实例状态是不是「运行中」（已关机自然连不上）
2. 登录指令有没有整行复制全（`ssh -p` 和端口都不能少）
3. 密码是不是多带了空格/换行
4. 公司/校园网有时会挡非标准端口 —— 换成 JupyterLab 通道即可绕过
</details>

## 4. 进去后的第 60 秒：四条命令

不管你走哪个入口，先打这四条，确认自己站在哪、有多少家底：

```bash
pwd                             # 我现在在哪个目录（刚进去通常是 /root）
ls -a                           # 这里有什么
df -h /root /root/autodl-tmp    # 系统盘 / 数据盘 各剩多少  ★ 最该看这条
nvidia-smi                      # 有没有 GPU
```

- `nvidia-smi` 显示一张 `RTX 4090` → 你走的是**有卡模式**，正在按 ¥1.88/时计费
- `nvidia-smi: command not found` → 你在**无卡模式**，这是正常的，不是坏了

## 5. Linux 只需要会这 6 条命令

| 命令 | 作用 | 例子 |
|---|---|---|
| `cd <目录>` | 进目录 | `cd /root/autodl-tmp` |
| `ls` | 看有什么 | `ls -lh`（带大小） |
| `mkdir -p <目录>` | 建目录 | `mkdir -p /root/autodl-tmp/data` |
| `cp` / `mv` | 复制 / 移动改名 | `mv a.tar.gz b.tar.gz` |
| `rm -rf <目录>` | **删**（不可恢复） | 慎用 |
| `cat` / `tail` | 看文件 | `tail -f train.log`（实时跟） |

三个省命技巧：

- **Tab 补全**：打前几个字母按 `Tab`，自动补全路径（少打错字）
- **↑ 上箭头**：翻出上一条命令，改一改再跑
- **`Ctrl+C`**：中断当前正在跑的东西（前台任务卡住时用这个）

## 6. 把代码传上去

**方式 A：JupyterLab 拖拽（最省事）**

1. 终端里先 `cd /root/autodl-tmp`
2. 把本地 `outputs/upload/vibnet_code.tar.gz`（4.5 MB）拖进左侧文件树
3. 回终端解包：
   ```bash
   cd /root/autodl-tmp
   tar -xzf vibnet_code.tar.gz
   cd vibnet-forgery-detector
   ls                     # 应能看到 src scripts configs docs README.md ...
   ```

   > 💡 代码包**自带顶层目录**，所以在 `/root/autodl-tmp` 里直接 `tar -xzf` 就对了，
   > **不需要** `mkdir -p` + `-C`。这一步是新手最容易出错的地方：解错位置时
   > 脚本会报"项目目录不存在"，但文件明明都在 —— 别怀疑自己没传成功。

**方式 B：本地 Git Bash 用 scp**（端口/主机看控制台 SSH 登录信息）

```bash
cd "D:/picture/vibnet-forgery-detector"
scp -P <端口> outputs/upload/vibnet_code.tar.gz root@<主机>:/root/autodl-tmp/
```

> ⚠️ 只传**代码包**。仓库里的 `data/` 有 43 GB，传上去要几个小时，
> 而云端下载同样数据只要几十分钟 —— 数据一律在云端重下（`docs/18` §2）。

## 7. 把结果取回来

- **JupyterLab**：左侧文件树里找到文件 → 右键 → **Download**
- **scp 反向拉**（本地 Git Bash）：
  ```bash
  scp -P <端口> root@<主机>:/root/autodl-tmp/vibnet_results_20260922.tar.gz ./
  ```

> 开实例期间传输很快，**别等到释放实例才想起来取结果** ——
> 释放 = 连同数据盘一起清空，不可恢复。

## 8. 跑任务：三种姿势，别用错

| 姿势 | 命令 | 终端/网页关掉后 | 什么时候用 |
|---|---|---|---|
| 前台 | `python scripts/train.py ...` | ❌ **任务会死** | 短跑、看报错（`probe`） |
| 后台 nohup | `nohup python -u ... > log.txt 2>&1 &` | ✅ 继续跑 | ★ 正式训练 |
| 后台 + 自动关机 | `nohup bash -c "python ...; /usr/bin/shutdown" &` | ✅ 跑完自己关机 | ★★ **最省钱** |

`scripts/cloud_autodl.sh train` 已经把第三种包好了，前台的 `probe` 用来先看速度。
重点记住这一条：**关掉 JupyterLab 标签页 ≠ 任务停止；但前台任务会死。**
长任务一律 `nohup`。

## 9. 怎么知道它还在干活

```bash
tail -f outputs/gpu_train_log.txt     # 实时看日志（Ctrl+C 退出，不影响训练）
nvidia-smi                            # 看 GPU 利用率、显存、进程
python scripts/check_status.py        # 三证据交叉判定"是死是活"
```

**判断任务活着没有，别看"日志一时没动"就下结论** —— 日志本来就是间隔写入的
（`log_every` 默认 50 个迭代）。可靠做法是三样一起看：进程在不在、
日志文件修改时间、日志里的进度数字有没有推进。

## 10. 停下来 / 关机 / 释放

| 想干什么 | 怎么做 | 后果 |
|---|---|---|
| 中断前台任务 | 终端里按 `Ctrl+C` | 任务停止，数据盘内容保留 |
| 停后台任务 | `ps -ef \| grep train` 找到 PID → `kill <PID>` | 同上 |
| **关机**（停止计费） | 控制台 →【关机】 | GPU 停止计费；数据盘内容**保留** |
| **释放** | 控制台 →【更多】→ 释放 | ⚠️ **机器和磁盘一起清空，不可恢复** |
| 自动释放 | 不用管 | 关机 15 天后系统自动释放 |

**关机前**：`sync` 一下，确认重要产物已 `pack` 并下载。

> 注意：**关机不保留那张卡**。按量计费下，第二天开机可能这台机器上已经没有
> 4090 了 —— 数据盘还在，但得换机器（项目放在数据盘上，所以能直接带走）。

## 11. 新手最常卡的 9 个场景

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 粘密码时屏幕上没动静 | Linux 不回显密码 | 正常，直接回车 |
| `Ctrl+V` 粘不进网页终端 | 浏览器截获了快捷键 | 用 `Ctrl+Shift+V` 或右键 Paste |
| `nvidia-smi: command not found` | 无卡模式 | 正常，不是故障 |
| `ssh: command not found` | 用错了 shell（如 CMD） | 改用 Git Bash / PowerShell |
| 任务莫名消失 | 前台跑，关掉了网页/终端 | 用 `nohup` 重跑 |
| `No space left on device` | 写到系统盘 `/root` 了 | 把项目挪到 `/root/autodl-tmp` |
| `找不到 ForenSynths` 之类 | `cd` 的目录不对，或 `--data-root` 少写了一级 | 先 `pwd` + `ls` 对照；新版会**自动补一级并提示** |
| 网页 IDE 打不开 | 实例不在「运行中」 | 回控制台确认状态 |
| **解包了代码，脚本却说"项目目录不存在"** | 解包位置不对（漏了 `-C` 会摊平到当前目录） | 文件其实都在。跑 `bash scripts/cloud_autodl.sh doctor`，它会**自动检测并把修复的 `mv` 命令原样打给你**（见 `docs/08` D35） |
| **`clip` 报"两个源都失败"，还提示走路线 B** | 大概率**不是网络问题**：torch 与 transformers 版本互斥 | `install` 会自动降级修复；手动 `pip install 'transformers==4.44.2'` 后重试（见 `docs/08` D38） |

## 12. 最小可用的完整流程（照抄）

```bash
# ① 进 JupyterLab → Terminal，第 60 秒确认
pwd; df -h /root/autodl-tmp; nvidia-smi

# ② 放代码（拖拽上传后）
cd /root/autodl-tmp && tar -xzf vibnet_code.tar.gz   # 自带顶层目录，不要再加 -C
cd vibnet-forgery-detector

# ③ 无卡模式阶段：准备（约 ¥5）
bash scripts/cloud_autodl.sh status    # 只读；随时可跑，告诉你走到哪一步了
bash scripts/cloud_autodl.sh doctor
bash scripts/cloud_autodl.sh install
bash scripts/cloud_autodl.sh clip
bash scripts/cloud_autodl.sh data
bash scripts/cloud_autodl.sh verify

# ④ 换成有卡模式开机，再回来
bash scripts/cloud_autodl.sh probe     # 先看要花多久、多少钱
bash scripts/cloud_autodl.sh train     # 正式跑，结束自动关机

# ⑤ 取结果
bash scripts/cloud_autodl.sh pack
# 然后在 JupyterLab 左侧文件树里右键 → Download
```
