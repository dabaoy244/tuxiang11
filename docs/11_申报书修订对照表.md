## 0. 先看这里：改的时机与三条铁律

### 时机

| 阶段 | 动作 |
|---|---|
| **现在（评审期）** | 🔴 **什么都不要改。** 评审期间提交修订稿 = 主动自曝材料不严谨 |
| 立项后 – 中期检查前 | 把本文 §1 §2 的内容整理成《研究内容调整说明》，随中期材料一起提交 |
| 中期检查后 | 落进正式的研究记录，结题报告按调整后的口径写 |

### 三条铁律（**这部分比具体条目更重要**）

**铁律 1：指标只能"细化口径"，绝不能"降低标准"。**

这是整份文档最关键的判断。同一个问题，两种改法命运完全不同：

| | ❌ 错误改法（会被质疑立项依据） | ✅ 正确改法（标准没降，只是说清了） |
|---|---|---|
| ACC | 「≥91%」→「≥88%」 | 「≥91%」→「在 ForenSynths **未见过的生成器子集**上 ≥91%」 |
| 体积 | 「≤120MB」→「≤400MB」 | 「≤120MB」→「**部署形态**（ONNX+INT8 量化后）≤120MB」 |
| 速度 | 「≥8 张/秒」→「≥2 张/秒」 | 「≥8 张/秒」→「**ONNX Runtime FP32、Intel i7 级 CPU、224×224、batch=1** 条件下 ≥8 张/秒」 |
| 消融 | 「7 项消融」→「不做消融」 | 「7 项消融」→「**4 项核心模块消融**（GS / 相位支路 / VIB / CS-CAM）」 |

**区别的本质**：前者是"我达不到所以改低"，后者是"我说清在什么条件下达到"。
后者在中期检查里是**加分项**（说明你真的做了预研），前者是**减分项**。

**铁律 2：把"缺陷"包装成"预研发现"。**

不要写"原申报书有误"。改写口径：
> "在前期预研与原型实现过程中，我们发现原方案在 XX 与 YY 之间存在需要明确的边界条件，
> 现基于实测数据对研究内容做如下细化调整。"

**铁律 3：所有修订都要有实测数据支撑。**

这也是这个项目目前的优势——`docs/09` 里的每个数字都是本机实测、可复现的。
**带着数据去谈修改，比空口说"做不了"强一百倍。**

### 🔴 致命 1 · 「相位贡献是幅值的 1.7 倍」查无出处

| 项 | 内容 |
|---|---|
| **位置** | 1.1(2) 频域分支论述 |
| **原文** | "相位信息对扩散模型生成图像的检测贡献是幅值信息的 1.7 倍" |
| **问题** | **全网检索不到任何文献给出这个量化结论。** 检索结果只有"相位比幅值更能决定图像结构"这个**定性常识**（属于信号处理通识，可追溯到 Oppenheim & Lim 1981 的经典实验），但没有任何论文测出过针对"扩散模型生成图像检测"的 1.7 倍。**凭空出现的精确倍数，是审稿人和答辩老师最容易抓的点。** |

**三种处理方式（按推荐度）**

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 自己测出来** | 做"仅幅值 vs 幅值+相位"的消融，在自己数据上算出真实倍数 | ⭐ **最优**。你本来就计划做这个消融（`ablation.py` 里有 `no_phase` 开关），把它变成数据来源，反而多一个创新点 |
| **B. 删掉倍数，改为定性+引经典** | 见下方改后文字 | 稳妥，零风险 |
| **C. 标注出处** | 如果确实有来源，把文献补上 | 只在真能找到出处时用 |

**可直接粘贴的改后文字（方案 B）**

> 相位谱编码了图像中各频率分量的空间位置与结构信息，对图像语义的决定性作用已被经典研究揭示

> <sup>[Phase Matching, arXiv:2307.12622]</sup>。在生成图像检测任务中，相位分量能否提供
> **独立于幅值的判别信息**，目前尚缺乏系统验证。本项目通过消融实验对此进行定量分析，
> 并在第 X 节给出结论。

> **方案 A 的加分写法**（做完消融后替换）：

### 🔴 致命 2 · 「模型体积≤120MB」与「CLIP-ViT-B/16 骨干」实测冲突

| 项 | 内容 |
|---|---|
| **位置** | 1.1(1) 指定骨干 vs 6.3 指标 |
| **实测冲突** | CLIP-ViT-B/16 视觉塔 **85.81 M 参数**，单骨干 FP32 = **349.8 MB**；加上全部模块共 90.53 M → **362.1 MB**，**超标 3.0 倍** |

| b16 + 动态 INT8 | 92.9 MB | 2.86 张/s | ✅ | ❌ |
| **s16 + FP32 + ONNX 简化** | **98.7 MB** | **9.46–11.22 张/s** | ✅ | ✅ |
| lite s16 + INT8 | 25.7 MB | 3.35 张/s | ✅ | ❌ |

> **显式的工程实验结论**进行报告，为同类轻量化检测模型的部署选型提供参考。

**配套的口径说明（中期检查时口头解释用）**

> "申报书 1.1(1) 的 CLIP-ViT-B/16 是**精度上限档**，我们完整实现了；
> 但实测其骨干单独就有 85.8M 参数、FP32 体积 362MB，与 6.3 的『≤120MB』直接冲突——
> 这两条在申报时没有对齐。所以我们把体积-精度权衡做成了一个显式实验：

### 🔴 致命 3 · 公式 (1)(3) 与 1.3(3) 的维度自相矛盾

| 项 | 内容 |
|---|---|
| **原文冲突** | 公式 (1)(3)：`φ(x) ∈ R^768`、`F_local ∈ R^128`、`F_spa ∈ R^896`（**向量**）<br>1.3(3)：定位支路使用"**512 维空频融合特征图（14×14×512）**"（**特征图**） |
| **为什么致命** | ① 向量与 3 维特征图不可能同时成立；② 更严重的是 `Concat(φ(x), F_local)` 得到 896 维**向量**，通道拼接后做 1×1 卷积，空间分辨率是 **1×1**，**不可能变成 14×14**；③ 若照公式实现，Mobile-UNetv2 的上采样没有任何空间信息可恢复，**mIoU 会接近 0**；④ 1.3(3) 的"512 维"与公式的 896 维也对不上 |
| **本项目实现** | 同时保留两种形式：CLS token 作 768 维全局语义向量（对应公式 1）；patch token 重排为 **14×14×768** 空间特征图；与局部纹理特征通道拼接得 **14×14×896** 的 F_spa；对 F_spa 做 GAP 即还原为公式 (3) 的 896 维向量 |

**可直接粘贴的改后文字**

> **公式 (3) 后补充**：上式中 `F_spa ∈ R^896` 为对融合特征图做全局平均池化后的向量表示；
> 其**特征图形式**记为 `F_spa ∈ R^{896×14×14}`，用于定位支路以保留空间分辨率。
>
> **1.3(3) 修订**：定位支路直接使用空频融合特征图 `F_spa ∈ R^{896×14×14}`
> （原"512 维"应为"896 维"，与公式 (3) 保持一致）。

### 🔴 致命 4 · 「梯度停止层」的描述与实际数学行为不符

| 项 | 内容 |
|---|---|
| **原文（1.3(1)）** | ① 分类梯度不回传至定位支路 ② 定位梯度不回传至分类支路 ③ F_fusion 同时接收两条支路的梯度 |
| **为什么致命** | 在"共享 F_fusion + 两个兄弟头"的朴素结构下，**①②③ 是自动成立的**——两个头之间没有计算图连线，梯度物理上不可能串扰。**把 GS 实现成恒等映射，数学行为和没加它完全一样。** 如果论文写"引入梯度停止层实现梯度隔离，从根本上解决任务间干扰"，审稿人一定会问"**你挡的是哪条路径？**"，答不上来只能撤回这句话 |
| **与三阶段训练的矛盾** | 阶段一/二靠冻结实现硬隔离；阶段三两者都解冻，若 GS 仍是恒等映射则"隔离"形同虚设；若真阻断一条，则③又不成立。**逻辑必须自洽** |
| **本项目实现** | `gradient_stop.py` 实现为**可配置的任务级门控**：`gs_stop_cls`（阻断分类梯度回传 F_fusion）/ `gs_stop_loc`（阻断定位梯度回传 F_fusion），默认关闭 |

**可直接粘贴的改后文字**

> **1.3(1) 修订**：本项目在共享空频融合特征层面实现**任务级梯度门控**机制。
> 阶段一、二通过参数冻结实现硬隔离（另一支路完全不参与优化）；
> 阶段三提供可选的梯度门控：当分类与定位任务在共享特征上出现梯度冲突
> （表现为两个任务的验证指标交替恶化）时，通过梯度停止层将共享特征的优化目标
> 限定为主任务，从而显式缓解多任务梯度冲突。该机制零额外计算开销，
> 与 PCGrad / GradNorm 属同类思路。
>
> **并新增一张消融表**：三种 GS 配置（均关 / 仅关分类 / 仅关定位）
> 在 ForenSynths ACC 与 CASIAv2 mIoU 上的对比。**有了这张表，"梯度隔离"这一节才立得住。**
